# Signed Release Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish immutable semantic releases without creating unsigned commits on protected `master`.

**Architecture:** Keep semantic-release's analysis, generated release notes, tags, and GitHub releases. Remove the prepare-stage changelog and Git plugins so the workflow tags the already signed commit instead of mutating the repository.

**Tech Stack:** Node.js 24, Node test runner, semantic-release 25, GitHub Actions

## Global Constraints

- Keep the verified-signature ruleset enabled.
- Do not publish this configuration as an npm package.
- Never move or rewrite a published release tag.
- Run the complete `npm test` quality gate before pushing.
